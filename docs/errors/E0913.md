# E0913: `ofir.lock` is out of date

With `--locked`, `build`, `run`, `test` and `fetch` fail instead of
changing `ofir.lock` (ADR 0032): the packages the graph resolves to must
be the ones the lock records, with their checksums. It is reported at the
`dependencies` of the root `ofir.json`, with a note for each package that
would be added, moved to another version or commit, or removed, or when
there is no lock at all.

Use it in CI, so that a build uses exactly the versions that were
committed.

## Example

```jsonc
{
  "name": "app",
  "dependencies": {
    // `ofir.lock` was written when this was `^1.2`
    "json": {"git": "https://example.com/json.git", "version": "^2.0"}
  }
}
```

## Fix

Run `ofir fetch` (or `ofir update`) without `--locked`, and commit the
`ofir.lock` it writes.
