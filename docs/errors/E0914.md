# E0914: a checksum differs from `ofir.lock`

`ofir.lock` records the SHA-256 of each git package's files (ADR 0032):
its files sorted by path, each as its path, a NUL, its size, a NUL and
its bytes, the `.git` directory left out. When the checkout of a package
at its locked commit hashes to something else, the package is not used:
the repository was rewritten, or the cache or the lock was changed by
hand. The notes give both hashes.

Path dependencies have no checksum.

## Example

```jsonc
// ofir.lock
{
  "packages": [
    {"name": "json", "git": "https://example.com/json.git", "version": "1.4.0",
     "commit": "1f0c…", "checksum": "0000…"}
  ]
}
```

## Fix

If the change is expected, remove the package from `ofir.lock` (or run
`ofir update json`) so that it is resolved and hashed again. Otherwise,
find out why the files of that commit changed before trusting them.
