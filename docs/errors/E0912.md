# E0912: no version satisfies every requirement

A program has one version of each git dependency: the highest tag
`vX.Y.Z` of its repository that every requirement on it accepts, across
the whole graph (ADR 0032). When there is none, resolution fails and
lists the requirements, with the project that made each one, and the
versions there are. There is no backtracking: an older version is not
picked silently.

It is also reported when the projects ask for different `rev` or `branch`
values of one repository, or for a revision it does not have.

## Example

```jsonc
{
  "name": "app",
  "dependencies": {
    "json": {"git": "https://example.com/json.git", "version": "^2.0"},
    // `http` requires `json` as `~1.4`
    "http": {"git": "https://example.com/http.git", "version": "^0.3"}
  }
}
```

## Fix

Make the requirements meet: here, require a `json` that `http` accepts
(`^1.4`), or move to a version of `http` that works with `json` 2.

```jsonc
{
  "name": "app",
  "dependencies": {
    "json": {"git": "https://example.com/json.git", "version": "^1.4"},
    "http": {"git": "https://example.com/http.git", "version": "^0.3"}
  }
}
```
